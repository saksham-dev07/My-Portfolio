# SAKSHAM.exe: orbital archive upgrade

## Audit before implementation

The existing optional /exe route, lazy module boundary, real boot milestones, three destinations, accessible HTML navigation, failure explorer, local progress, reduced-motion preference, and return-position handling work and stay in place. Installed R3F, Drei, Three, and Lucide are sufficient. No new package or external asset is needed.

The scene is a single Canvas with orbit controls, a procedural Fibonacci neural sphere, three identical torus/octahedron markers, a grid floor, ambient/directional/point lighting, and camera interpolation. There are no textures, shadows or post-processing costs. Individual neural nodes unnecessarily create one draw call per node. Quality changes node density and DPR. Mobile compresses the same layout. Project and skill selection only change HTML; there is no physical relationship between destinations. The context panel appears before the camera arrives. Reset snaps home even with motion enabled. There is no visual payoff for discovering all three areas.

## Art direction

Digital consciousness interpreted as an orbital archive. Ink-blue architectural forms, porcelain/periwinkle signal light, violet relationships, copper personal details. The central core is an instrument storing connections; outer structures imply a larger archive. Projects are purposeful artifacts, skills are relationships, About is a quiet observatory. Avoid the generic grid, unrelated particles, excessive bloom and additional worlds with thin content.

## Preservation and validation

Retain the current route, boot, exit, menu, storage and WebGL fallback. Keep readable text in HTML. Reuse verified project data. No audio, physics, paid assets, new backend, invented biography, or unrelated normal-portfolio refactoring. Balanced remains the normal default; mobile detail is independently bounded. Check production build, desktop/mobile composition, reduced motion, fast interrupted navigation, artifact/skill selection, completion, quality changes and initial-route network isolation. Record measured renderer counts separately from hardware-dependent performance claims.

## Implemented and checked

- Retained the original router, boot milestones, controls, menu, storage and exit flow. Added two scene components within the existing deferred world module. No new dependency or external asset.
- Removed the grid and repeated octahedron markers. Added orbital terraces, distant instanced archive ribs, a responsive instanced core, three purpose-specific portal forms, and connected signal paths.
- Travel uses a bounded 1.45-second wall-clock transition. New destinations interrupt the current journey; reduced motion settles immediately. Opening a menu or toggling motion no longer restarts a completed journey. HTML reading panels appear after arrival.
- The five existing projects have selectable physical artifacts and readable details. Skill selection changes real connections: React has three links to the featured archive; Python has two. Additional related projects remain accessible through the existing text list.
- The quiet personal observatory uses verified education years, a small interactive coffee object, and the existing profile. Completion changes the core's palette and reveals a contact invitation; contact remains available through About throughout.
- Checked 1280 × 720 desktop, 390 × 844 mobile, and 320 × 800 narrow mobile. Adjusted the bottom sheet to leave all five artifact controls visible. Verified project selection, skill filtering, About discovery, completion, menu focus wrapping, reduced-motion controls, rapid destination switching, readiness, and footer return.
- Production network capture on the normal route contained zero SakshamExe/ExeWorld requests. Browser error/warning log was empty during final interaction checks.
- Measured hub: 48 draw calls, 19,072 triangles in desktop Balanced; 48 draw calls, 16,640 triangles in the mobile tier; zero GPU textures in both. No shadows or post-processing. Renderer diagnostics are exposed on the canvas data attributes for repeatable checks. Frame timing in a background browser is throttled and is not a reliable hardware FPS benchmark; physical low-end phones still require device testing.
- `bun run check`, `bun run build`, and all seven existing tests (33 assertions) passed. No deployment or remote write performed.
- Cinematic verification: 48 hub draw calls, 22,240 triangles, zero textures. Returned the preview to Balanced after checking the mode.
